# Keynote Visual System — 视觉规范

## 视觉 DNA

**不是**把技术概念包裹在一堆漂亮的 UI 卡片里，而是像产品发布会一样：用最小数量的物体和精确的空间关系讲一个结构故事。

1. **洁净**：大面积白色/雾白，轻微冷调渐变。画面留白占较高比例，主体周边能呼吸。
2. **有触感**：哑光白瓷 / 磨砂聚合物 / 少量银色金属，统一低强度柔光。避免油亮、液态金属、大片高透明玻璃。
3. **亲和**：白色圆润无脸人偶、像精品工业模型的厨房、商店、卡片或流程图元素，尺寸可亲，手势简练。
4. **理性**：对齐精准、线条清楚、主次克制；不是儿童绘本、科幻电影或 UI 示意图堆叠。
5. **可讲述**：看起来就像演讲者可以站在 Keynote 前解释 30 秒的概念图。

## 推荐色彩语义

| 用途 | 参考值 | 解释 |
|---|---|---|
| 主背景 | `#F7F8FA` | 微冷雾白 |
| 主体材质 | `#F2F2F0` | 乳白陶瓷 |
| 深色文字（仅有字时） | `#1D2D46` | 深海军蓝灰 |
| 主流程 | `#568FE8` | 克制的 Apple 式蓝 |
| 浅蓝表面 | `#DDEAFB` | 轻盈蓝色辅层 |
| 次要节点/连接 | `#A8B0BC` | 中性灰 |
| 许可/完成 | `#BFE1CC` | 低饱和薄荷绿 |
| 提醒/风险 | `#EABF83` | 柔和琥珀色 |
| 禁止/失败 | `#D88986` | 少量柔红 |

颜色是含义，不是装饰。一个图中不超过 2 个主色 + 1 个强调色，除非内容确实需要。

## 造型与空间

- 统一 3/4 视角或轻微轴测，或者统一平视角；不要在同一层突变透视。
- 模块以圆角矩形、圆盘基座、简化实体模型表达，避免套娃式多层透明卡片。
- 阴影软、短、淡；主体像是坐落在同一张白色摄影棚无缝背景上。
- 人偶是角色标识而不是吉祥物，场景涉及角色时可使用，系统架构图则用抽象对象表示更清晰。
- 物件识别优先：旅游用行李/酒店/汽车；厨房用灶台/菜单/厨师；架构用消息/枢纽/工位/数据库。
- 连线是信息架构的一部分。主路径蓝色连续实线；条件、备选或观察路径轻灰/蓝虚线；禁止关系用断线或一个明确的阻断符号。

## 文字与版式

- 无字模式必须真正无字，不出现伪文字、随机英文、数字、屏幕代码、商标。
- 有字模式区分标题、核心角色名和次级职责说明。标题留在页眉，把最大的画面面积留给最重要的角色。技术名用于识别（如 `Router`），只有在职责不够直观时才补一行短动作（如“接单 · 派单 · 回传”）。辅助模块的字号、对比和面积均低于主图。
- 技术名保留原写法（如 `A2UI`、`Intelligent UI`），不得随意改名或自动扩写概念。
- 演示文稿视觉的核心是：漂亮但不替讲解者说完整段话。

## 分层架构样图

[分层架构样图](../assets/reference-layered-architecture.png) 的视觉重点是接近中性的白底，淡蓝集中在中心长台、角色服装和连线；圆头无五官的人偶保持同样的造型，执行工位小而等大。左上是紧凑标题，左侧是分层导读，中央长台是最大主体，右侧工具栏使用更小的尺寸和更轻的阴影。延续此画风时，把这些特征写在已附参考图的提示词里，避免整幅底色泛蓝或角色变成写实插画。遇到其他层级关系，可保留材质、人物比例和字体层级，重排版式。

## 过去图像的经验教训

- 过多宫格、重复小人物、说明卡片会导致“解释很多，但一眼看不懂”。
- 生成图片里的长中文常会有错字，所以默认减少文字密度。
- 架构图更适合分层关系而非连续摆五十个模块盒子；命名精确，分组清晰。
- 商业模式关系要准确表达“谁掌握关系/付款/触达”而不只是画出一台机器人。
- 比较图应该在共同基准下对照，如 A2UI / Intelligent UI / 代码生成中的资源来源、可变性、执行主体不能错位。
- 高亮只服务于一个结论：蓝色连接主链路，风险用一处暖色，不要每个角落都有彩色发光体。
