# 结构版式与图解方法

## A. 三段流程：最常用

**适用**：一个机制如何把输入转成输出，或中间层如何改变双方关系。

- 横向排版 `起点 → 中间机制 → 结果`。
- 每段一个主体和一条明确的关系线。
- 角色、物件、连线优先；切勿在每个节点里堆 4 条解释。
- 范例：`用户 → 超级导购 → 店家`，若“交易权”改变，增加钱的流向并切断商家直接联系顾客的线。

## B. 三栏对比：同一事例、三个规则

**适用**：A2UI / Intelligent UI / 代码生成，三种技术路线或产品方案。

- 三栏使用同一视角、同一旅程或同一业务场景，让真正的规则差异凸显。
- 每栏最多一个主场景和一个可见状态机制，不要重复整套景点酒店餐厅。
- 范例：`固定行程` vs `预案条件分支` vs `自由生成但被沙箱圈住`。
- 共同条件采用相同象征物；差异通过路线分叉、围栏或修改权限来表示。

## C. 两栏机制：有形解释 vs 抽象推演

**适用**：物理引擎 vs 世界模型，传统机制 vs 新机制。

- 左栏具体因果：物体、作用力、接触结果、规律路径。
- 右栏整体环境：状态表示、未来分支、预测候选。
- 两栏视觉分量相等，不把右侧无缘由画成“更厉害”的超级大脑。

## D. 层级架构：中心调度、多单元并行

**适用**：Super-agent / Router–Worker / 事件驱动系统。

- 首层：输入/事件来源。
- 第二层：触发与准入、路由/协调中心。
- 第三层：工作单元并行，避免把调度器误画成执行全部任务的人。
- 第四层：结果回传与人的注意力/审批面板。
- 底层或旁侧：持久状态与独立监控/守护机制。
- 最粗最亮的箭头表示主业务流；回馈、监控、状态读写用次一级线条；不能把状态库误当工作流中的一个会话。
- 对需要严格复原某篇文章的图，应先获取原文，识别明确提到的组件，不能依“常见架构”自行添加。

## E. 坐标/权衡曲线

**适用**：能力 vs 效率、通用性 vs 延迟等典型取舍。

- 真实绘制横轴和纵轴，方向必须与说明匹配。
- 若说明是“更强但更慢”，右侧能力更强时纵向效率应更低（曲线总体下降）。
- 用 2–4 个代表对象锚定曲线，最多一个弱化的未来/理想指向；不把概念曲线误称真实测量数据。
- 无字模式可以用闪电、计时器、可覆盖任务数量等图形做含义提示；文字模式优先标轴而非堆说明段落。

## F. 简洁单场景

**适用**：一段话只有一个真正要表达的隐喻。

- 使用一个完整场景，不分三栏，不制造五张缩略卡片。
- 范例：“前厅负责派单，后厨各管一口灶” → 一个前台调度员 + 右侧 3–5 个独立灶台；视觉重心放在前台和并行关系。
- 当用户说“更简单”，先退回这个结构，再决定要不要额外分组。

## 图像生成前的一句话自测

“用户不读文字，只看元素摆放和箭头，是否能准确区分谁能决定、谁能执行、资源来自哪里、变化是否被允许？”

不能的话，先改结构再追求质感。
